# FluxGate 项目总览

## 1. 项目定位

FluxGate 是团队内部使用的代理流量网关控制面板。它把多个零散机场、上游订阅和节点资源统一纳入节点池，再通过 sing-box 数据面把这些资源包装成统一的团队网关节点。

FluxGate 关注“管理和控制”，sing-box 关注“真实转发和统计”。这条边界可以让项目保持清晰：

```text
FluxGate = 控制面
sing-box = 数据面
```

## 2. 要解决的问题

现状问题：

- 上游机场和零散节点来源多，难以统一管理。
- 团队成员拿到原始订阅后，很难控制有效期、权限和流量额度。
- 如果只是重新组合订阅，真实代理流量不会经过管理端，无法统计真实用量。
- 某个成员到期、离队或异常跑量时，需要能快速停用。

目标结果：

- 管理员只维护一个 FluxGate 控制面。
- 团队成员只拿 FluxGate 生成的订阅。
- 客户端实际连接 FluxGate 网关节点。
- sing-box 将流量转发到后端上游节点。
- 每个用户、Token、虚拟节点、上游节点的流量都可以统计。
- Token 到期、禁用、超额后可以在网关层生效。

## 3. 核心原则

1. 所有客户端订阅只暴露 FluxGate 网关入口，不暴露原始上游节点。
2. 所有真实代理流量必须经过 sing-box 数据面。
3. 用户身份以 Token/UUID 映射到 sing-box inbound user。
4. 权限控制以团队、标签、策略和额度为核心。
5. 统计以 sing-box 的用户、入站、出站维度为基础，FluxGate 负责持久化和汇总。
6. 到期和超额不能只拦截订阅更新，还必须刷新数据面配置。
7. HTTPS 内容不做解密，不做 MITM，只统计流量和连接元数据。

## 4. 第一版范围

MVP 先打通最短可运营闭环：

- 管理员登录。
- 创建团队和成员。
- 创建 Token，设置有效期和流量额度。
- 导入上游节点 URI 或上游订阅。
- 给节点打标签。
- 配置团队可用的标签/地区/出口组。
- 生成客户端订阅。
- 生成 sing-box 配置。
- 启动 sing-box 网关。
- 采集每个用户的流量。
- Token 到期、禁用、超额后自动从 sing-box 配置中移除或切到拒绝策略。

## 5. 暂不做的内容

第一版不做这些复杂能力：

- 不做 HTTPS 内容解密。
- 不做复杂审计和敏感内容识别。
- 不做多服务器集群调度。
- 不做完整计费系统。
- 不做高度动态的无重启热更新，先接受配置校验后重启 sing-box。
- 不做过于复杂的客户端适配，优先支持 Clash Meta/Mihomo 和 sing-box 客户端。

## 6. 成功标准

第一版完成后，应满足：

- 管理员可以在 Web 面板创建用户、Token、额度和有效期。
- 用户可以通过订阅地址导入客户端并正常代理。
- 原始上游节点不会直接暴露给团队成员。
- FluxGate 可以看到每个用户的真实用量。
- 禁用或过期用户后，新连接无法继续使用。
- 服务器可以通过 Docker Compose 一键部署在 `/home/wings/docker/FluxGate`。
