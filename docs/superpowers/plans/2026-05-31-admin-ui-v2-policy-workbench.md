# Admin UI v2 策略边界工作台增量计划

## 目标

策略模块决定团队、成员或 Token 能看到哪些虚拟网关和上游节点，是“真实可测”前最后一道访问边界。当前策略列表已经卡片化，但用户进入模块后仍需要逐条看卡片才能判断是否启用、是否限额、是否绑定网关。本增量在不改动后端接口的前提下，为策略列表增加首屏工作台，让访问边界先可扫读，再进入单条策略编辑。

## 范围

- 在策略列表顶部新增策略边界工作台。
- 展示策略总数、启用策略、节点上限和网关边界 4 个关键状态。
- 展示策略作用域分布卡，按团队、成员、Token 或其他作用域聚合，并显示启用、限额和网关边界数量。
- 保留现有策略卡片、行内编辑、保存和取消动作。
- 补静态 UI 契约和浏览器视觉 QA，校验工作台存在、关键符号存在、作用域卡片存在且无视觉溢出。

## 验证

1. 先扩展 `scripts/qa/ui-static.sh` 和 `scripts/qa/browser-login.sh`，确认缺少策略工作台时静态检查失败。
2. 实现 `renderPolicyWorkbench` 与对应 Calm Ops 样式后重新跑静态检查。
3. 运行完整本地验证套件，覆盖桌面和移动视觉 QA。
4. 清理临时文件、执行公开仓库脱敏扫描。
5. 提交、推送、部署，并用远程可用性探测确认控制面与订阅网关仍可真实测试。
