# FluxGate Admin UI v2 视觉系统设计

## 背景

上一轮后台 UI 已经具备模块化导航、概览、接入、节点、身份、策略、流量和运维等功能入口，但视觉结果仍显得拥挤、补丁感重、层级不稳定。用户明确反馈“越改越丑”，因此本轮不再继续局部叠加按钮和提示，而是以新的视觉参考图为基准，重建后台的视觉壳层、页面节奏和控件规范。

本设计只覆盖管理后台前端体验，不改变后端 API、Token 安全模型、订阅生成、sing-box 配置生成和部署脚本。

## 目标

1. 后台第一屏呈现成熟、现代、克制的运维控制台，而不是临时拼装页面。
2. 保留现有真实测试闭环：登录、接入上游、同步节点、地区聚合、节点详情、Token 分发、复制 Mihomo/sing-box 订阅、发布网关配置、查看状态。
3. 统一按钮、输入框、筛选器、卡片、表格、抽屉和状态徽标尺寸。
4. 长节点名、长来源名、长订阅地址和长标签不能撑破父容器。
5. 常用动作要在当前上下文内完成，新增/编辑表单必须收纳到折叠区或侧滑抽屉。
6. UI 变更必须能通过桌面和移动截图验收，不再只靠静态选择器判断。

## 视觉基准

采用“轻量控制台”方向：

- 背景：浅灰蓝或浅中性背景，避免大面积深色或花哨渐变。
- 表面：白色卡片和面板，细边框，轻阴影，最大 8px 圆角。
- 导航：桌面固定左侧栏，移动底部 Dock；导航只承载模块切换和关键数量，不承载复杂说明。
- 状态色：蓝色用于主操作，绿色用于健康，琥珀用于待处理，红色用于异常。
- 排版：中文界面，标题紧凑，内容密度接近运维控制台；禁止英雄页式大标题和营销式说明。
- 装饰：不使用紫色大渐变、光球、背景 blob、过度插画。

## 页面结构

### Shell

后台整体结构固定为：

- 左侧导航：FluxGate 标识、7 个模块、数量徽标。
- 顶部工具条：当前状态、刷新、退出；不再新增全局复杂命令面板。
- 工作区标题：模块名、简短描述、主操作、筛选/搜索入口。
- 内容区：按模块展示卡片、表格、抽屉和详情。

顶部和工作区标题必须轻量，不得因为摘要、提示条和快捷入口叠加而压缩正文。

### 概览

概览页第一屏只回答三件事：

- 网关是否正常运行。
- 现在是否能真实测试。
- 下一步应该点哪里。

布局包含：

- 一条真实测试状态条。
- 4 到 6 张关键指标卡。
- 上游健康分布。
- 地区分布或节点分布。
- 最近同步和最近审计两个紧凑表格。

### 订阅管理

订阅管理聚合现有接入和身份模块里的核心任务：

- 上游来源列表和刷新状态。
- 生成订阅地址区域。
- Token 到期时间和客户端格式选择。
- 通用、Mihomo、sing-box 三类订阅地址长期可复制。
- 一键探测订阅地址是否可访问。

新增来源、手动导入、签发 Token 等表单默认收纳，不常驻铺满页面。

### 节点池

节点页默认显示地区聚合卡片：

- `🇨🇳中国|香港`
- `🇨🇳中国|台湾`
- `🇺🇸美国`
- `🇯🇵日本`
- `🇸🇬新加坡`
- `其他`

地区卡片展示节点数量、健康比例、协议分布和异常数量。点击地区后进入节点列表，节点卡片标题最多两行，超出省略；点击卡片打开详情抽屉。详情抽屉展示完整节点信息，编辑只开放安全字段：展示名、地区覆盖、标签、备注、命名模式。

### 令牌与审计

身份和审计页重点服务订阅分发：

- Token 生命周期表格。
- 到期、额度、状态徽标。
- 每个 Token 的订阅地址入口。
- 流量趋势和异常访问记录。
- 审计日志按东八区展示。

## 交互规则

### 表单

- 新增和编辑使用右侧抽屉或模块内折叠面板。
- 桌面抽屉宽度控制在 420 到 560px。
- 移动抽屉全屏展示，并避开底部 Dock。
- 抽屉标题区固定保存和取消。
- `Escape` 收起抽屉但保留草稿；取消按钮清空草稿。
- 提交中禁用控件并显示明确动作文案。

### 操作按钮

- 保存、创建、发布使用主按钮。
- 编辑、刷新、复制、打开、探测使用紧凑工具按钮。
- 图标按钮必须有可访问标签。
- 按钮文字不得被截断成不可理解的半截。

### 长文本

- 节点名最多两行，完整内容放入详情抽屉或 tooltip。
- 订阅地址使用等宽字体、内部省略和复制按钮。
- 表格列使用固定或弹性宽度，单元格内部省略。
- 卡片主体必须设置 `min-width: 0`，禁止内容把 grid/flex 撑破。

## 实施策略

采用渐进重建，而不是一次性替换全部前端：

1. 先清理旧实验和过度叠加的 UI 入口，恢复稳定基线。
2. 重建 Shell 和基础视觉变量，让页面先像一个统一产品。
3. 重做概览第一屏，建立真实测试状态、指标卡和紧凑表格节奏。
4. 重做节点池和 Token 区域，优先解决用户最痛的长文本溢出、订阅复制和节点详情。
5. 最后整理移动端 Dock、侧滑抽屉和浏览器 QA。

## 验收标准

每个增量必须至少满足：

- `scripts/qa/ui-static.sh` 通过。
- `scripts/qa/browser-login.sh` 在桌面视口通过。
- 关键页面截图无横向溢出、无遮挡、无文字撑破。
- 临时文件清理完成。
- 公开仓库脱敏扫描通过后才允许提交和推送。

最终验收必须覆盖：

- 桌面 1440x900。
- 桌面 1280x720。
- 移动 390x844。
- 长节点名、长来源名、长订阅地址和长标签。
- Token 三类订阅地址反复复制。
- 节点地区聚合、节点详情抽屉和安全字段编辑。
