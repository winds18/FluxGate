# 审阅清单

这份清单用于你审阅当前方案时逐项确认。

## 1. 产品定位

- [ ] FluxGate 是否确认只做控制面板，不自己转发真实代理流量？
- [ ] sing-box 是否确认为唯一数据面核心？
- [ ] 是否接受第一版不做 HTTPS 内容解密，只统计流量和连接元数据？
- [ ] 是否接受第一版不暴露原始上游节点给团队成员？

## 2. 用户和权限

- [ ] 团队、用户、Token 三层模型是否符合你的管理方式？
- [ ] Token 是否需要支持多个设备限制？
- [ ] Token 是否需要绑定 IP？
- [ ] Token 默认有效期是多少？
- [ ] Token 默认流量额度是多少？
- [ ] 超额后是直接禁用，还是限速？

## 3. 客户端协议

- [ ] 第一版入站协议是否确认使用 VLESS？
- [ ] 是否需要同时支持 Shadowsocks？
- [ ] 客户端主要是 Clash Meta/Mihomo、sing-box，还是其他？
- [ ] 订阅格式第一版是否只做 Clash/Mihomo 和 sing-box？

## 4. 虚拟节点

- [ ] 虚拟节点是否按地区划分，例如 HK/SG/US/JP？
- [ ] 是否需要 Premium/Gaming 等业务标签？
- [ ] 第一版是否接受不同 virtual node 使用不同入口端口？
- [ ] 是否需要共用 443 端口？

## 5. 上游节点

- [ ] 上游主要是机场订阅 URL 还是零散 URI？
- [ ] 第一版是否先支持手动 URI 导入？
- [ ] 是否需要自动同步上游订阅？
- [ ] 节点标签是否由管理员手动维护？
- [ ] 节点展示名是否默认使用来源前缀？
- [ ] 来源前缀格式是否采用 `[来源名] 节点名`？
- [ ] 手动修改过的节点名是否应避免被后续同步覆盖？

## 6. 流量统计

- [ ] 统计维度是否需要用户、Token、虚拟节点、上游节点四类？
- [ ] 流量周期是自然月、30 天滚动，还是自定义？
- [ ] 是否需要订阅响应头展示剩余流量？
- [ ] 是否需要导出流量报表？

## 7. sing-box 发布策略

- [ ] 第一版是否接受配置变更后重启 sing-box？
- [ ] 是否要求尽量不中断已有连接？
- [ ] 是否需要配置版本回滚？
- [ ] 是否需要发布前人工确认？

## 8. 部署

- [ ] 部署路径是否只存在于本机未跟踪配置或服务器 `.env` 中？
- [ ] 远程仓库是否通过当前 Git remote 或显式 `REMOTE_URL` 配置？
- [ ] 是否已有域名？
- [ ] 是否已有反代 Caddy/Nginx？
- [ ] 管理后台是否需要限制访问 IP？
- [ ] 如果需要局域网访问，是否仅在部署侧配置 `FLUXGATE_HOST_BIND=0.0.0.0`，而不是提交真实环境信息？
- [ ] 镜像构建是否默认走 GitHub Actions 或远程构建？
- [ ] 本地是否只做验证，不承担生产镜像构建？
- [ ] 部署脚本是否必须先执行系统环境探测？
- [ ] 磁盘 warning/critical 阈值是否采用 80%/90%？
- [ ] 磁盘快满时允许自动清理哪些内容？
- [ ] 部署失败时是否必须自动采集诊断日志？
- [ ] 推送前是否执行 `scripts/qa/public-scan.sh` 并通过？

## 9. MVP 验收

- [ ] 管理员能创建用户和 Token。
- [ ] 用户能通过订阅导入客户端。
- [ ] 客户端真实流量经过 sing-box。
- [ ] FluxGate 能看到用户真实流量。
- [ ] Token 到期后无法新建连接。
- [ ] Token 超额后无法新建连接。
- [ ] 配置发布失败时不会覆盖可用配置。
- [ ] 管理后台页面有截图或视觉验收记录。
- [ ] 部署和验收日志可追踪。

## 10. 待决策问题

当前最需要你拍板的是：

1. 第一版入口协议：只做 VLESS，还是 VLESS + Shadowsocks？
2. 第一版虚拟节点：独立端口，还是共用 443 分流？
3. 流量周期：自然月，还是从 Token 创建日起 30 天？
4. 超额策略：禁用，还是限速？
5. 管理后台：是否需要公网访问，还是只允许固定 IP/VPN？
