# Admin UI v2 接入来源工作台增量计划

## 目标

接入模块是导入节点和真实测试闭环的第一步。当前来源列表已经卡片化，但首屏缺少“是否健康、是否可自动刷新、是否有异常”的总览。本增量在不改动后端接口的前提下，为来源列表增加模块级工作台，让用户先扫健康，再进入单卡片编辑和刷新。

## 范围

- 在来源列表顶部新增接入来源工作台。
- 展示来源总数、健康来源、自动刷新、异常来源 4 个关键状态。
- 展示来源类型分布卡，区分订阅来源、手动来源等类型，并显示已同步和自动刷新数量。
- 保留现有来源卡片、编辑、刷新和同步命名动作。
- 补静态 UI 契约和浏览器视觉 QA，校验工作台存在、关键符号存在、类型卡数量足够且无溢出。

## 验证

1. 先扩展 `scripts/qa/ui-static.sh` 和 `scripts/qa/browser-login.sh`，确认缺少工作台时静态检查失败。
2. 实现 `renderSourceWorkbench` 与对应 Calm Ops 样式后重新跑静态检查。
3. 运行完整本地验证套件，覆盖桌面和移动视觉 QA。
4. 清理临时文件、执行公开仓库脱敏扫描。
5. 提交、推送、部署，并用远程可用性探测确认控制面与订阅网关仍可真实测试。
