# FluxGate Admin UI Calm Ops Design

## 背景

用户已明确选择「A. 冷静指挥台」作为 FluxGate 管理后台的新方向，并补充要求：交互一定要人性化。当前后台虽然已有侧边导航、移动 Dock、概览入口和部分模块化能力，但视觉质感、信息密度、长文本处理、编辑入口和真实测试链路的顺畅度仍不足，不能作为可交付的管理体验。

本设计只覆盖管理后台 UI/UX 重构，不改变控制面 API、sing-box 网关生成逻辑、Token 安全模型和部署脚本。后续实现必须保持现有真实可用链路：登录后台、接入上游、同步节点、按地区查看、编辑节点展示信息、创建团队/用户/Token、复制订阅地址、用 Mihomo/sing-box 获取订阅、发布网关配置、查看运行状态。

## 设计目标

1. 后台第一眼必须像一个成熟的运维控制台，而不是临时拼装页面。
2. 所有模块都遵循同一套视觉语言、控件尺寸、间距和状态反馈。
3. 长节点名、长订阅地址、长标签列表不能撑破卡片、按钮、表格或移动端视口。
4. 常用操作少跳转、少打扰：复制订阅、刷新来源、查看节点详情、编辑展示名、发布配置都要在当前上下文内完成。
5. 真实测试链路要清晰：用户能从概览页看到下一步、拿到真实订阅地址、确认客户端类型，并知道网关配置是否已发布。
6. 移动端可以完成查看、复制、刷新、轻量编辑，不要求承载复杂批量管理。

## 视觉方向

采用「冷静指挥台」视觉语言：浅灰蓝背景、白色或半透明表面、深色桌面侧边栏、绿色健康状态、克制的蓝色主操作。整体避免单一紫蓝、强渐变、装饰性光斑和过度圆角。界面应该安静、清楚、耐看，适合反复运维使用。

桌面端使用固定左侧导航，右侧为内容工作区。移动端隐藏侧边栏，改为底部 Dock。内容区使用模块标题、上下文摘要、快捷入口和主面板分层，不再把所有表单和列表直接堆在同一屏。

控件统一规则：

- 页面区块和卡片圆角最大 8px。
- 主按钮、次按钮、危险按钮高度统一，文案和图标垂直居中。
- 输入框、下拉框、文本域宽度占满所在列，不出现同一表单里大小错乱。
- 表格单元格、节点卡片标题、订阅地址使用省略、换行或复制按钮处理，禁止横向撑破。
- 状态颜色只表达状态，不作为大面积装饰。

## 信息架构

后台保留 7 个一级模块，但重新定义每个模块的第一屏任务：

- 概览：展示系统健康、真实测试闭环、资源数量、订阅与网关状态、下一步操作。
- 接入：管理上游来源、刷新来源、添加来源、手动导入节点。
- 节点：默认显示地区聚合；进入地区后显示节点卡片；点击节点卡片打开详情抽屉；节点展示名、前缀、标签和备注可编辑。
- 身份：管理团队、成员、Token；Token 卡片直接展示可复制订阅地址，并提供 Mihomo/sing-box 格式切换。
- 策略：管理团队、成员、Token 与节点范围的可见关系。
- 流量：展示 Token、用户、出口、时间维度的统计摘要，保持东八区时间显示。
- 运维：检查配置、发布配置、回滚配置、重启 sing-box，并展示最近一次操作结果。

## 人性化交互原则

### 入口清晰

每个模块第一屏只放该模块最常用的 2 到 4 个操作。低频表单默认收纳在折叠面板或抽屉中，用户点击「新增」「编辑」「导入」后再展开。概览页的快捷卡片直接跳到对应模块和关键区域。

### 反馈及时

任何提交、刷新、发布、复制、测试请求都必须有可见反馈。按钮进入 loading 状态时文案变成明确动作，例如「正在刷新」「正在发布」。成功后显示简短结果，失败后保留用户输入并展示可操作错误原因。

### 少打扰

非危险操作不弹阻断式确认。危险操作，例如回滚配置、重启网关、删除或禁用 Token，使用确认弹层或二次确认按钮。普通编辑使用抽屉内保存，不离开当前列表。

### 可恢复

编辑表单应支持取消并恢复原值。节点来源、节点展示名、前缀命名模式支持「恢复自动」操作，但必须说明恢复后的预期结果，例如展示为自动前缀和自动名称。

### 真实测试友好

Token 区域必须能基于当前访问来源生成真实订阅地址，而不是要求用户手动拼域名。订阅地址卡片提供：

- 默认订阅地址复制。
- Mihomo 地址复制。
- sing-box 地址复制。
- 一键探测订阅可访问性。
- 最近一次探测时间和结果。

复制成功后给出明确反馈，不用用户猜剪贴板是否成功。

### 导航减负

概览页快捷入口不应只切换模块后让用户继续找位置；入口必须直接定位到对应的列表、节点池、Token 或运维操作区。模块标题区的上下文摘要和面板入口采用横向可扫的命令条，桌面端保持第一屏稳定，移动端保持可滑动和可点击，不因为数量变化把工作区挤乱。

## 关键页面设计

### 概览页

概览页顶部展示 4 个指标：节点池数量、上游来源数量、可用 Token 数、网关状态。下方是「真实测试闭环」面板，按顺序展示数据源、节点池、Token、订阅、网关发布的完成状态。未完成项显示下一步按钮；已完成项显示最近时间和查看入口。

概览页不展示大段说明文字，只展示状态和操作。所有说明通过短标签、Tooltip 或错误详情承载。

### 节点页

节点页默认是地区聚合视图，每个地区卡片展示地区名称、国旗、节点数量、协议分布和异常数量。没有地区信息的节点进入「其他」。台湾和香港统一显示为「🇨🇳 中国|台湾」「🇨🇳 中国|香港」。如果节点名表达路径，例如「香港-美国」，归属终点地区「🇺🇸 美国」。

点击地区卡片进入节点列表。节点列表使用卡片网格或紧凑表格切换。卡片标题最多两行，超出使用省略，鼠标悬停或详情抽屉展示完整名称。点击节点卡片打开详情抽屉，展示来源、协议、服务器、端口、地区、标签、URI Hash、命名模式、展示名和最近同步时间。

节点编辑只开放安全字段：展示名、地区覆盖、标签、备注、命名模式。原始 URI、服务器和协议默认只读，避免误改导致节点不可用。

### 身份与订阅页

Token 是真实测试的核心对象。Token 卡片需要展示：Token 名称或前缀、所属用户、到期时间、额度、当前状态、默认订阅地址、客户端格式按钮。复制按钮使用固定宽度图标按钮和短文案，地址本身使用等宽字体、自动换行和省略，不撑破布局。

创建 Token 后不只显示一次结果，还要在 Token 列表中长期可重新获取订阅地址。用户不应依赖创建瞬间的临时提示。

### 表单与抽屉

新增和编辑统一使用右侧抽屉或模块内折叠面板。抽屉宽度在桌面端限制为 420 到 560px，移动端占满宽度。抽屉顶部固定标题、保存、取消按钮；底部不放隐藏的关键操作。表单字段按逻辑分组，必填字段有明显标识，错误信息贴近字段显示。

### 移动端

移动端使用底部 Dock，最多展示 5 个高频入口；低频模块进入「更多」或通过概览快捷入口进入。列表卡片单列显示，详情抽屉变为全屏面板。底部 Dock 不遮挡页面最后一项，页面底部保留安全间距。

## 空状态与错误状态

空状态必须告诉用户下一步能做什么，而不是只显示「暂无数据」。例如：

- 没有来源：显示「添加订阅来源」和「手动导入节点」。
- 没有 Token：显示「创建 Token」并提示创建后可复制订阅地址。
- 没有节点：显示最近同步错误或引导刷新来源。
- 配置未发布：显示「检查配置」和「发布配置」。

错误状态必须包含可读原因和下一步动作。后台日志链路仍用于调试，但 UI 不能只要求用户去看日志。

## 可访问性与可维护性

所有交互控件必须可通过键盘聚焦并有明确焦点样式。按钮不能只靠颜色表达状态。图标按钮必须有可访问标签或标题。动态状态使用文本同时表达，不只依赖颜色。

前端实现应拆分渲染函数，避免继续扩大单个巨型文件的认知负担。优先在现有静态前端结构内渐进拆分，不引入大型前端框架。

## 验收标准

实现完成后必须通过以下验收：

1. 桌面 1440x900、1280x720、移动 390x844 三个视口截图无重叠、无横向溢出、无文字撑破父容器。
2. 使用长节点名、长来源名、长订阅地址、长标签列表测试，卡片、表格、抽屉都保持稳定布局。
3. 登录后能进入概览页，不停留在登录页。
4. Token 列表能反复复制默认、Mihomo、sing-box 订阅地址。
5. 节点页默认展示地区聚合，进入地区后能打开节点详情抽屉并编辑安全字段。
6. 所有时间展示使用 Asia/Shanghai。
7. 浏览器视觉 QA、项目测试、清理脚本、公开仓库脱敏扫描全部通过。

## 非目标

本轮不引入复杂主题编辑器，不做营销首页，不做全量前端框架迁移，不改变后端鉴权模型，不实现与 Mihomo 客户端的本机自动导入。Mihomo 真实可用性通过订阅内容格式、复制地址和外部客户端导入验证。
